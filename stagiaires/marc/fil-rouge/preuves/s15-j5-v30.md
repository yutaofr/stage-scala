# Preuve S15 J5 — Qualification v3.0

Date d'exécution : 14 juillet 2026

Seed : `1500`

Volume : `1000`
Rejet déterministe : une transaction interne toutes les 10 transactions

## Exécution

Le broker a été recréé avant le gate, puis le producer et le consumer ont été
lancés :

```bash
sbt 'runMain clearing.v30.runTransactionProducerV30 \
  --count 1000 --seed 1500 --rate 1000 --reject-every 10'
sbt 'runMain clearing.v30.runKafkaConsumerV30 \
  --group-id marc-v30-review-fix --max-records 1000'
```

Résultat :

```text
PRODUCER_V30 attempted=1000 acknowledged=1000 failed=0
CONSUMER_V30 published=1000 duplicates=0 failedPartitions=0
```

Les log-end-offsets donnent :

```text
clearing-input:  605 + 203 + 192 = 1000
clearing-output: 537 + 192 + 171 = 900
clearing-dlq:     32 +  34 +  34 = 100
```

Le groupe a committé 605, 203 et 192, avec un lag nul sur les trois partitions.
Le test pur parallèle au gate recalcule les positions des 900 succès et obtient
une somme globale égale à zéro.

## Confidentialité

Les 900 événements de sortie et les 100 événements DLQ ont été relus avec clé,
headers et value, puis soumis au motif `MA[A-Z0-9]{22}` :

```text
clearing-output full_record_raw_iban_matches=0
clearing-dlq    full_record_raw_iban_matches=0
```

La DLQ conserve un fingerprint SHA-256 et une erreur stable, jamais le payload
original.

## Limite

Ce gate valide un laboratoire local mono-broker. Il ne prouve ni tolérance à la
panne du broker, ni réplication, ni sécurité réseau, ni exactly-once avec un
système externe.
