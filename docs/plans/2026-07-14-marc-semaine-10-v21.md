# Marc Week Ten Typed Railway Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Deliver Marc's Clearing Engine v2.1 with one typed `Either` railway per input line, safe Java and file boundaries, explicit recovery warnings, and error statistics.

**Architecture:** Add `clearing.v21` beside the accepted v2.0 core. A numbered line crosses parse, validation, recovery, forex, fee, and anonymization stages in one `for` comprehension; the batch partitions `Either` values once and nets only successes. Extend the shared sealed error hierarchy and add backward-compatible `Try` APIs at Java boundaries.

**Tech Stack:** Scala 3.3.8 standard-library `Either` and `Try`, ScalaTest 3.2.19, existing immutable domain and v2.0 netting, SBT 1.10.11, Java 17 and 21.

**Step 3: Implement the per-line `for`**

Expose a `HashBoundary = String => Either[TechnicalError, String]`. Implement:

```scala
def processLine(
  config: V21Config,
  seenIds: Set[Int],
  hash: HashBoundary
)(line: NumberedLine): Either[ClearingError, RailSuccess] =
  for
    parsed <- EitherCsvParser.parse(line)
    valid <- RailValidation.validate(config, seenIds)(parsed)
    recovered <- RailRecovery.recover(valid)
    converted <- applyForex(config)(recovered)
    charged <- applyFee(config)(converted)
    secured <- anonymize(hash)(charged)
  yield secured
```

Implement `process` with an immutable `foldLeft` carrying seen accepted IDs
and ordered results. Partition once, calculate statistics by matching the
sealed hierarchy, adapt successes to `PreparedTransaction`, and reuse
`PureNettingCalculator.positions`.
