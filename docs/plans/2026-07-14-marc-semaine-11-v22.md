# Marc Semaine 11 v2.2 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Livrer un Clearing Engine v2.2 dont le chemin actif utilise des types opaques et exporte le même domaine en JSON, CSV ou XML avec des type classes Scala 3.

**Architecture:** Ajouter un paquet versionné `clearing.v22` afin de préserver les jalons S1–S10. Les factories convertissent les primitives aux frontières; le railway manipule ensuite `BankCode`, `Iban` et `Money`. Des instances `given` choisies localement alimentent un `ExportEngine` générique et les extensions de format.

**Tech Stack:** Scala 3.3.8, bibliothèque standard Scala, `scala.compiletime.testing`, ScalaTest 3.2.19, SBT 1.10.11, Java 17 et 21.

Créer :

```scala
object DomainTypes:
  opaque type BankCode = String
  opaque type Iban = String
  opaque type Money = BigDecimal

  object BankCode:
    def from(raw: String): Either[String, BankCode]
    def unsafe(raw: String): BankCode

  object Iban:
    def from(raw: String): Either[String, Iban]
    def unsafe(raw: String): Iban

  object Money:
    def apply(value: BigDecimal): Money
    def parse(raw: String): Either[String, Money]
    val zero: Money

  extension (code: BankCode)
    @targetName("bankCodeValue") def value: String

  extension (iban: Iban)
    @targetName("ibanValue") def value: String
    def bankSegment: String

  extension (money: Money)
    def value: BigDecimal
    def +(other: Money): Money
    def -(other: Money): Money
    def *(rate: BigDecimal): Money
    def abs: Money
    def isPositive: Boolean
    def format: String

  given Numeric[Money]
```

Normaliser avec `Locale.ROOT`. Autoriser trois ou quatre lettres pour
`BankCode`. Valider exactement vingt-quatre caractères alphanumériques et le
pays `MA` pour `Iban`. Grouper les milliers sans dépendre de la locale JVM.
