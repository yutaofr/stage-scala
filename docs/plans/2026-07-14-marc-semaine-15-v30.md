# Marc Semaine 15 v3.0 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Livrer un Clearing Engine v3.0 Kafka KRaft, at-least-once et testable, en réutilisant strictement le cœur v2.3 de Marc.

**Architecture:** `clearing.v30` adapte les événements Kafka au railway v2.3. Un coordinateur pur impose l'ordre traitement, publication confirmée, déduplication puis commit par partition. Les adaptateurs Kafka restent aux bords et la DLQ ne transporte aucun IBAN brut.

**Tech Stack:** Scala 3.3.8, Apache Kafka client et image 4.3.0, Circe 0.14.13, ScalaTest 3.2.19, ScalaCheck 1.18.1, Docker Compose, Java 21 et Java 17.

**Step 1: Write failing offset tests**

Construire deux partitions et vérifier que le coordinateur publie avant de
marquer, marque avant de committer, committe `offset + 1`, calcule une entrée
par partition et ne dépasse jamais un record dont la publication échoue.

**Step 2: Implement the coordinator**

Le coordinateur séquentiel retourne les offsets autorisés. Le loop Kafka
désactive l'auto-commit, poll, groupe les records par partition, publie via un
producteur séparé et appelle `commitSync` uniquement avec les offsets autorisés.
Un échec retourne aussi le premier offset à rejouer; le loop fait `seek` avant
le poll suivant. Un shutdown hook appelle `wakeup` puis ferme proprement
consumer et producer.

**Step 3: Verify GREEN and Docker integration**

Exécuter les specs ciblées, puis consommer les 50 événements et vérifier
`output + dlq = input` ainsi que les offsets du groupe.

**Step 1: Write failing crash-window tests**

**Step 2: Implement the in-memory registry**

Encapsuler un `ConcurrentHashMap`. Le registre distingue nouveau, replay du
même ID/fingerprint et conflit du même ID avec un autre fingerprint. Un replay
ne republie pas; un conflit est acquitté en DLQ. Documenter qu'un crash avant le
marquage peut republier.

**Step 3: Verify RED mutation then GREEN**

Inverser temporairement marquage et publication : le test doit échouer. Restaurer
l'ordre correct, exécuter la suite et capturer un replay Docker d'un offset non
committé.
